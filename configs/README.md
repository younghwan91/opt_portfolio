# configs/ — 공개 예제와 비공개 운용 설정

여기 남는 것은 **스키마를 보여주는 합성 예제 둘뿐**이다.

| 파일 | 무엇인가 |
|---|---|
| `strategy.json` | 전략 선언 전체 필드를 한 번씩 보여주는 예제. 문헌 표준 팩터 12종·중대형주 밴드·방어 장치 켜짐. **채택 전략이 아니다.** |
| `space.json` | `optimize` 탐색 공간 예제 |

## 왜 예제만 두는가

**엔진은 공개하고 파라미터는 공개하지 않는다.** 딥러닝 저장소가 모델 코드와
학습 스크립트는 내놓고 체크포인트는 안 푸는 것과 같은 구분이다. 여기서
체크포인트에 해당하는 것은 walk-forward **학습 구간 안에서 고른 파라미터** —
팩터 조합·시총 밴드·종목 수다.

이유는 성과가 아니라 **용량**이다. 채택 전략의 유니버스는 초소형주이고, 이
규모에서는 같은 종목을 사는 사람이 몇십 명만 늘어도 체결가가 밀린다. 보유
종목만 감추는 것으로는 부족하다 — **시총 밴드와 팩터 조합이 종목을 결정하기
때문에, 레시피가 있으면 같은 종목이 나온다.**

## 규칙

| | 어디에 두는가 |
|---|---|
| 합성 예제 | `configs/strategy.json` · `configs/space.json` (공개, 이 둘뿐) |
| 연구·실험 설정 | **저장소 밖** — 예: `~/data/configs/strategy_band15.json` |
| 실제 운용 파라미터 | **저장소 밖** — 예: `~/data/configs/strategy_live.json` |
| 검증 리포트 HTML | **공개** — `reports/` (파라미터 값은 가림) |

## 무엇을 공개하고 무엇을 가리는가

경계는 **성적과 레시피** 사이에 있다. 성과·방법론·검증 절차는 공개하는 것이
이 저장소의 목적이고, 가리는 것은 **파라미터의 값** 하나뿐이다.

| | |
|---|---|
| ✅ 공개 | 성과 지표 · 검증 리포트 · 방법론 · 엔진 전체 · 158팩터 정의 · 기각 기록 |
| ❌ 비공개 | 채택 팩터 조합 · 시총 밴드 · 보유 종목 수 · **보유 종목** |

보유 종목이 비공개인 이유는 성과가 아니라 **역산**이다. 보유 종목의 시가총액을
훑으면 밴드가 그대로 드러나고, 밸류에이션 지표를 보면 팩터 성향이 읽힌다.
종목을 공개하면서 레시피를 감추는 것은 성립하지 않는다.

**레시피가 사는 곳은 JSON 만이 아니다.** 설정 19개를 걷어낸 뒤에도
`reports/2026-08-13-…html` 본문이 종목 수와 시총 구간을 그대로 서술하고
있었고, `07-experiment-log.md` §6 도 마찬가지였다 (2026-08-16 발견). 둘 다
확장자 기준 점검이 놓친 자리다. 그래서 값이 아니라 **모양**을 보는 검사를
pre-commit 에 걸었다 (`scripts/check_no_parameter_values.py`) — 패턴에 실제
숫자를 적으면 그 검사 파일 자체가 유출이 되기 때문이다.

리포트는 그 두 문장만 가리고 **본문 전체를 공개한다.** 검증 서사·DSR 논의·
레짐 IC·남은 위험은 파라미터 없이도 온전하고, 그것이 리포트의 값어치다.

`--config` 는 임의 경로를 받으므로 코드 변경이 필요 없다.

```bash
opt-factor optimize --store ~/data/us_micro.duckdb \
  --config ~/data/configs/strategy_live.json --space configs/space.json
```

## 어떻게 막는가

방어는 화이트리스트다. **기본이 차단이고 위 두 파일만 예외**다.

1. `.gitignore` 가 `configs/*.json` 을 통째로 무시하고 예제 둘만 되살린다.
2. pre-commit 훅(`no-private-strategy-configs`)이 `git add -f` 로 뚫은 경우까지
   커밋 단계에서 막는다.
3. CI 의 `Pre-commit` 잡이 같은 검사를 다시 돌린다 — 로컬 훅은 `git clone` 한
   순간 사라지기 때문이다. 실제로 이 저장소가 그렇게 잃었고, 그 사이에
   설정 19개가 공개 상태로 쌓였다.

이름 규칙만으로 막던 이전 방식은 **새 이름을 쓰는 순간 통과했다.** 되돌릴 수
없는 실수는 열거가 아니라 화이트리스트로 막는다.

## 되돌릴 수 없다는 점

이 장치들은 **앞으로** 를 막을 뿐이다. 한 번 푸시된 설정은 히스토리·포크·
GitHub 캐시에 남아 사후에 감출 수 없다. 유출된 열쇠와 같아서, 비공개로
가려면 **파라미터를 새로 도출하는 수밖에 없다.**

채택 파라미터는 2026-08-15 이전 히스토리에 공개돼 있었다. 그것은 공개된 v1 로
남으며, 실운용 파라미터는 방어 장치를 켠 상태의 재측정으로 새로 도출한다.
